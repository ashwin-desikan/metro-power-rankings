## 1. Architecture recap (so this can be picked up cold)

A standard game is three files:

- **HTML shell** — `public/play/games/<slug>.html`. Links `assets/styles.css`,
  a data pool, and an engine. Contains the fixed DOM the engine drives
  (`#card`, `#q`, `#opts`, `#reveal`, `#finale`, passport/progress, the
  `🔊 Read it to me` button) plus a `.grown` note stating the curriculum mapping.
- **Pool** — `public/play/games/pools/<slug>.js`. Sets
  `window.GAME = { BASE, HEADER, POOL_PICK, POOL }` then the engine reads it.
- **Engine** — `assets/engine.js` (shared MCQ loop: sample, shuffle options, TTS,
  sound, confetti, passport stamps, finale) or a specialised engine like
  `assets/lt-engine.js` (League Table Detective).

Pools are generated by Python under `scripts/games/` from `public/data/**` JSON,
then `scripts/games/clean_game_pools.py` normalises them. New MCQ games need only
a pool builder plus a copy-adapted HTML shell. New mechanics need a new engine.

### Shared MCQ data contract (`assets/engine.js`)

```js
window.GAME = {
  BASE: "https://rankings.citizenofnowhere.org",
  HEADER: { logoEmoji, logoText, title, grown, finaleH, finaleP, again },
  POOL_PICK: 8,                 // questions sampled per play
  POOL: [
    {
      city, flag, place, sub, stamp,   // scene / identity
      q,                                // the question text (also read by TTS)
      opts: [ { t, e?, logo? } ],       // 2–4 options; t = label, e = emoji, logo = crest URL
      ans,                              // index of correct option
      fact,                             // shown on reveal
      url, linkLabel,                   // deep link back to the site
      bg                                // scene background (CSS)
    }
  ]
};
```

Any game whose interaction is "read a prompt, pick the right option" slots
straight onto this engine. Only the pool builder is new.

### Design compliance (non-negotiable, per DESIGN-STANDARDS.md)

- Phone-clean at 390px, no page-level horizontal scroll. Any table-bearing game
  needs `min-w-0` on the grid child.
- Rank-first tables pin the identity column (`data-sticky-col="2"`).
- Keep the `🔊 Read it to me` affordance on every game; several target players
  still lean on it.
- Every game ends with the `.grown` note: audience (KS2 / US grade), the exact
  skills, and an age band.

### P0 — Game 1: In the Club (Boolean logic / sets)

**Why first.** Sorting countries by "in the EU **and** NATO" vs "in the UN **but
not** the EU" *is* set theory, and set theory is the Boolean logic behind every
`if` statement. It looks like geography and is actually the first programming
lesson. Highest leverage for the coding goal, and pool-only to build.

**Data.** `public/data/country-orgs.json` — map of `slug -> { ORG: status }`,
e.g. `australia: { APEC: Member, Commonwealth: Member, G20: Member, OECD: Member, UN: Member }`,
`albania: { EU: Candidate, NATO: Member, UN: Member }`.

**Mechanic (MCQ, ramped).**
- Level 1 (membership): "Which of these is in the **European Union**?" One correct, distractors are non-members.
- Level 2 (NOT): "Which country is in the UN but **NOT** the EU?"
- Level 3 (AND): "Which country is in **both** the G20 **and** the OECD?"
- Level 4 (OR / status nuance): treat `Candidate`/`Observer` as "not a full member" and quiz the distinction.

Introduce the words **and / or / not** explicitly in the `fact` reveal — that
vocabulary is the payoff.

**Pool builder.** `scripts/games/build_in_the_club.py`: load `country-orgs.json`,
pick a target org set per question, compute members / non-members / intersections,
emit `opts` + `ans`. Cap to well-known orgs (UN, EU, NATO, G20, G7, Commonwealth,
OPEC, African Union, ASEAN) so options are recognisable. Use country flags via the
existing flag source; deep-link `url` to the country page.

**Grown note.** "Boolean logic and sets (and / or / not) using real membership of
the UN, EU, NATO and more. KS2 reasoning; a first taste of the logic behind coding.
Ages 7–10."

**Example POOL entry.**
```js
{ city:"🌍", flag:"🇦🇺", place:"Australia", sub:"Country", stamp:"🧩",
  q:"Which country is in BOTH the G20 and the OECD?",
  opts:[{t:"Australia",e:"🇦🇺"},{t:"Nigeria",e:"🇳🇬"},{t:"Egypt",e:"🇪🇬"}],
  ans:0,
  fact:"Australia is in the G20 AND the OECD. Nigeria is in neither; Egypt is in the G20 but not the OECD.",
  url:"https://rankings.citizenofnowhere.org/countries/australia",
  linkLabel:"See Australia on the site →", bg:"linear-gradient(#eaf4ff,#fff)" }
```

### P0 — Game 2: Higher or Lower (binary search)

**Why.** The classic guessing game *is* binary search, the single most important
idea in early computer science. Teach the rule "always guess the middle" and the
player discovers the algorithm independently, on numbers they half-remember.

**Data.** `metros.json` (`pop`, `gdp`, `skyscrapers`, `metroStations`) or
`billionaires.json` (`networth`). A hidden target value; the player narrows a range.

**Mechanic (new engine `assets/hl-engine.js`).**
- Show a target: "I'm thinking of a city's population between 1 and 25 million."
- Each guess returns **higher** / **lower**; a live number line shades the
  eliminated range.
- Score on **few guesses**, not speed. After a win, surface the coaching line:
  "You found it in 4 guesses. Guessing the middle each time is called *binary
  search* — it's how computers find things fast."
- Ramp: widen ranges (population → net worth in billions) so halving matters more.

**Engine notes.** Small standalone engine: keep the `#q`, `#opts` (Higher /
Lower buttons or a numeric input for older play), TTS, and finale DOM so styling
is shared. Persist a "best guess count" per range in memory (JS var only, no
localStorage per artifact rules if ever embedded).

**Grown note.** "Binary search: narrow a range by halving it. Estimation, place
value into the millions, and the core idea behind how computers search. Ages 7–10."

### P0 — Game 3: How Many Times Bigger? (ratio & scale)

**Why.** Converts fast multiplication into **proportional reasoning**, the maths
that unlocks Year 5–6. The player's numbers already reach the millions from
existing games, so "London is ~1.3× New York by people, but New York's GDP is
nearly 2× London's" is reachable and genuinely surprising.

**Data.** `metros.json`: `pop`, `gdp`, `marketCap`, `skyscrapers`, `metroStations`,
`universities`. Real anchors: New York `pop 22,342,624`, `gdp 2477.8` ($bn),
`skyscrapers 347`; London `pop 16,821,649`.

**Mechanic (MCQ).**
- "About how many times bigger is New York than London by people?" → options
  `1.3×`, `2×`, `5×` (round to sensible buckets).
- Ramp: exact-ish ratios; mixed metrics ("bigger by people but smaller by GDP?");
  three-way comparisons.
- Always show the two raw numbers on the scene so the division is visible, then
  reveal the worked estimate in `fact`.

**Pool builder.** `scripts/games/build_times_bigger.py`: pick metric + two metros
with a clean-ish ratio, compute the bucket, build distractors one bucket away.
Prefer metros the player knows (top 40, cities with teams).

**Grown note.** "Ratio, division and estimation with real city data. Rounding and
place value into the millions and billions. Ages 7–10."

### P1 — Game 4: How Long Between? (timelines & elapsed years)

**Why.** Feeds directly on the player's memory for years. `leaders/**` runs back to
`achaemenid-empire.json` and `akkadian-empire.json`, so "who ruled at the same
time" and "how many years ago" become subtraction across centuries and the start
of real historical thinking.

**Data.** `leaders/**` (reign start/end per office), `olympics/editions` (every 4
years → multiples of 4), `country-facts.json` `formationDate` (e.g. US `1784`).

**Mechanic (MCQ, ramped).**
- "How many years between the Los Angeles 1984 Olympics and London 2012?" (÷4 too)
- "Who ruled **first**?" ordering across leaders.
- "Which two leaders were in charge **at the same time**?" overlap detection.
- Later: BCE/CE crossing with the ancient empires ("how long ago did the Akkadian
  Empire begin?").

**Pool builder.** `scripts/games/build_how_long_between.py`: sample dated events,
compute gaps/order/overlap, guard BCE/CE sign. Reuse the Leader Time Machine data
loading if already factored.

**Grown note.** "Timelines: elapsed years, ordering, centuries, BCE/CE, and
overlapping reigns using real leaders and Olympics. Ages 7–10."

### P1 — Game 5: Per Person (rates & averages)

**Data.** `country-indicators.json`: `gdpUsd`, `gdpPerCapitaUsd`, plus population.
**Mechanic (MCQ).** "This country's total GDP is huge, but shared across many
people. Which has the higher GDP **per person**?" Teaches that big total ≠ big
per-person, i.e. the idea of a rate/average. Ramp into "estimate GDP per person
given total and population." Reuse `engine.js`.
**Grown note.** "Rates and averages: total vs per person, and big-number division.
Ages 8–10."

---

### P1 — Game 6: How Far? (coordinates & distance)

**Why.** Extends the existing North/South game into real coordinates and scale, a
Year 4+ jump, and quietly rehearses the grid logic behind the Bee-Bot/treasure-map
work.
**Data.** `metros.json` `lat`/`lon` (NY `40.7128, -74.006`; London `51.5074,
-0.1278`).
**Mechanic (new engine).** "Which city is **closer** to London?" using
great-circle distance; or place a city roughly on a lat/lon grid. Start with
"closer/further" (no formula), then reveal approximate km. A light custom engine
with a simple world-grid SVG; keep shared header/finale.
**Grown note.** "Coordinates, distance and scale with real city positions. Ages
8–10."

### P2 — Game 7: Time Zones

`country-facts.json` `timezones`. MCQ: "It's 3pm in London. What time is it in New
York?" Time arithmetic and a gentle first meeting with negative offsets. Reuse
`engine.js`.

### P2 — Game 8: Spot the Overperformer

`overperformer.csv` + `metros.json`. MCQ: "Both cities are about the same size —
which one has **more** skyscrapers / teams / companies than you'd expect?" Real
data literacy: correlation and outliers. This is, in miniature, the analysis the
site itself does. Reuse `engine.js`.

### P2 — Game 9: Sort the Cities

`metros.json`. New drag-to-order engine: arrange 5–10 metros by a chosen stat.
Teaches sorting and comparison chains; later, show a "swaps" counter to hint at
why some orders are faster to build than others.

### P3 — Game 10: Metro Connections (graphs)

`twin-metros.csv`, `similar-metros.json`, `rail-hub.csv`, `megaregions.csv`.
Nodes and edges: "which cities are connected?", then shortest-path. The graph is
the data structure behind maps, networks and routing — a big concept, worth
saving until the earlier games have landed.

## 3. Recommended build order

1. **In the Club** (P0, pool-only) — highest coding leverage, cheapest build.
2. **How Many Times Bigger?** (P0, pool-only) — biggest maths stretch, cheapest build.
3. **Higher or Lower** (P0, new engine) — the binary-search centrepiece.
4. **How Long Between?** (P1, pool-only) — leans on an existing strength (years).
5. Then P1 Per Person / How Far?, then P2, then the graph game last.

Front-loading the three pool-only games gets three high-value titles live for the
cost of three Python builders and three copy-adapted shells, before any new engine
work.

## 4. The coding bridge (why these, specifically)

Each new game maps to a concept the player will meet again in Scratch, micro:bit
and Python, already understood:

| Game | CS concept it seeds |
|------|--------------------|
| In the Club | Boolean logic, sets, conditionals (`if A and not B`) |
| Higher or Lower | Binary search, algorithmic efficiency |
| Guess the Metro (future) | Decision trees, elimination |
| Sort the Cities | Sorting, comparison |
| Metro Connections | Graphs, nodes/edges, shortest path |
| How Many Times Bigger? / Per Person | Ratio, rates, estimation (the maths under data work) |

**Co-builder step (separate track).** A "Make Your Own Quiz" mode — pick a dataset,
write the `q`/`opts`/`ans`, generate a shareable pool — turns the player from
consumer into author. That is his first real experience of writing logic, on data
he owns. Worth scoping once two or three of the above ship.

## 5. Content cautions

- Keep `conflicts.json` out of children's games.
- Frame `billionaires.json` strictly as **magnitude** (place value, division), not
  aspiration; note the source flags some entries (e.g. a `⚠️` name marker) — strip
  markers in the builder.
