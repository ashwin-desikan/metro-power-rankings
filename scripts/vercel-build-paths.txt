# Single source of truth for "paths that feed `next build`".
#
# Read by BOTH scripts/vercel-ignore.sh (decides whether Vercel builds a
# pushed commit) and .githooks/prepare-commit-msg (decides whether to
# auto-append "[vercel skip]" to a commit that doesn't touch any of these).
# One list, two consumers, so they cannot drift apart the way the two
# jobs.toml copies did on 2026-08-06.
#
# One path per line. Blank lines and lines starting with # are ignored.
# Anything NOT listed here (mac-mini-jobs/, HANDOFF.md, docs, workbooks,
# all of scripts/ including this file and vercel-ignore.sh itself -- see the
# note below, raw pipeline dirs) never needs a deploy on its own.

postcss.config.mjs
tsconfig.json
package.json

.npmrc
vercel.json

# NOT listed, deliberately, since 2026-08-06:
#   scripts/vercel-ignore.sh
#   scripts/vercel-build-paths.txt
#
# They used to be here as a "safety net": change the guard, get a deploy. But a
# deploy of byte-identical output proves nothing about the guard, and it is not
# free. Merge commit 1c135d5bc was the 14th production build of 2026-08-06 and
# changed ZERO bytes of site output -- it touched only the guard, the hooks, the
# audit script, CI and docs. Six more commits that day were in the same shape.
#
# The guard now has a REAL proof that costs nothing: scripts/test-vercel-ignore.sh,
# 20+ cases pinned to real commits, run in CI as test.yml's vercel-ignore-guard
# job. That is strictly better evidence than an identical rebuild.
#
# vercel.json and .vercelignore DO stay above: those genuinely change deployment
# behaviour (headers, what gets uploaded), not just the decision to deploy.
