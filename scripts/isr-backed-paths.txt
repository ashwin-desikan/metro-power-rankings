# public/data paths the SITE CAN REFRESH WITHOUT A BUILD.
#
# Read by .githooks/post-commit, to tell the two very different meanings of a
# [vercel skip] commit that touches public/ apart:
#
#   entirely within this list -> the documented ISR exception. The commit is
#       live within the route's revalidate window; skipping the build is both
#       correct and complete.
#   anything outside it       -> the change is in the repo and NOT on the site.
#       It reaches production only when something next builds.
#
# WHY THIS FILE EXISTS. The hook used to call EVERY public/-scoped bot data
# commit "the documented ISR exception", which is false for most of
# public/data: CLAUDE.md is explicit that lib/ and app/ hold 313 readFileSync
# sites baking public/data in at build time, and that the ISR-backed files are
# the MINORITY. On 2026-09-22 a commit correcting eight election dates printed
# "the documented ISR exception" while those dates were nowhere near the live
# site -- the *-elections.json files are read with readFileSync, with no raw
# fallback and no revalidate. The outcome was right (a skip was wanted) but
# the stated reason was wrong, and a session trusting it would believe the
# site had been updated when it had not.
#
# The hook's old comment said this list could not be built "without a real
# per-file audit nobody has done". It can, mechanically, because an ISR-backed
# file is exactly one fetched from raw.githubusercontent.com at request time.
# TO RE-DERIVE after adding a live feed, from the repo root:
#
#   grep -rh -A2 "raw.githubusercontent.com" lib app --include="*.ts" \
#        --include="*.tsx" | grep -oE "public/data/[^\"'\`\$ ]*"
#   grep -rhoE 'loadLiveJson(<[^>]*>)?\(\s*"[^"]+"' lib app --include="*.ts" \
#        --include="*.tsx" | grep -oE '"[^"]+"'
#
# The second one matters because lib/liveData.ts holds a shared GH_RAW_BASE and
# every loadLiveJson() call site inherits it without naming the host itself.
#
# One prefix per line, relative to public/data/. A line naming a directory
# covers everything beneath it. Blank lines and # comments ignored.
# Derived 2026-09-22.
#
# ⚠️ THIS LIST IS CONSERVATIVE AND KNOWINGLY INCOMPLETE, because the two kinds
# of error are not symmetric:
#
#   wrongly EXCLUDED -> the hook says "not live, needs a build" about a file
#       that was already live. Mildly noisy, harmless, self-correcting: add
#       the path here.
#   wrongly INCLUDED -> the hook says "live, no build needed" about a file
#       that is NOT on the site. That is precisely the bug this file exists
#       to kill, and it is silent.
#
# So a path goes in ONLY once its reads are shown to go through a
# GitHub-raw-first loader. When in doubt, leave it out. The hook's wording is
# written to match: it says a file is "not on the ISR-backed list", never that
# it is definitely not ISR-backed, and invites the reader to add it.
#
# Proof required before adding a directory prefix: every read of anything
# beneath it goes through the raw fetch, AND no other module reads it at build
# time. nfl/elo, nfl/odds and nfl/seeds were added this way -- each of their
# five load() call sites pairs a `${GH_BASE}/${file}` fetch (revalidate
# 86400) with the matching readFileSync, and lib/nflElo.ts is the only module
# that touches them.
